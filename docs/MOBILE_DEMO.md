# 아이폰 로컬 픽업 앱 시연

앱스토어 배포용 네이티브 앱이 아니라 Safari에서 설치하는 PWA입니다. 실제 아이폰 홈 화면에서 독립 실행되며 Web Push를 구독합니다. 결제는 시연용으로 생략합니다. 매장 선택 → 메뉴/옵션 → 장바구니 → 주문번호 → 픽업 알림 흐름입니다.

## 실행 순서

1. PC와 아이폰을 같은 개인 와이파이에 연결합니다. 게스트 와이파이의 기기 간 접속 차단은 해제해야 합니다.
2. PC에서 **`start.bat`**을 실행하고 **2번 아이폰 시연**을 선택합니다. 또는 가상환경에서 `python app.py --mode mobile-demo`를 실행합니다.
3. 관리자 로그인 후 운영 센터를 열어 둡니다. 초기 비밀번호는 `1234`이며 변경했다면 변경한 비밀번호를 사용합니다.
4. 콘솔에 표시된 **`http://PC주소:9080/`**를 아이폰 Safari에서 엽니다. 이 주소는 인증서 설치 안내와 공개 인증서만 제공하며 주문 API나 개인 키를 제공하지 않습니다.
5. Safari에서 `아이폰 인증서 프로파일 다운로드` → 허용 후 **8분 안에 설정 → 일반 → VPN 및 기기 관리**에서 `BDS 로컬 시연 인증서`를 열어 **설치**를 완료합니다. 다운로드만으로 설치되지는 않습니다. 프로파일에는 공개 루트 인증서 하나만 들어 있으며 개인 키나 기기 관리(MDM) 설정은 없습니다. 직접 생성한 프로파일이므로 `서명되지 않음`이 표시될 수 있습니다. 인증서 SHA-256 지문을 PC 콘솔과 대조하세요.
6. **설정 → 일반 → 정보 → 인증서 신뢰 설정**에서 해당 인증서의 전체 신뢰를 켭니다.
7. 준비 페이지의 **BDS 픽업 열기** (`https://PC주소:9443/mobile/`)를 누릅니다. 인증서 경고 없이 접속되는지 확인합니다.
8. Safari 공유 → **홈 화면에 추가** 후 홈 화면의 **BDS 픽업** 앱을 엽니다. 설치한 앱에서 먼저 알림을 허용하고 주문하세요.
9. 앱 설정 또는 주문 내역의 **픽업 푸시 알림 켜기**를 누르고 권한을 허용합니다.
10. 앱에서 시연 주문을 만들고, PC 운영 센터 → **주방 종합창**에서 해당 `A` 주문을 접수한 뒤 조리 완료 처리합니다.
11. 아이폰 앱을 뒤로 보내거나 화면을 잠근 상태에서 접수/완료 알림을 확인합니다. 알림을 누르면 주문 내역이 열립니다.

Windows 방화벽 알림이 나타나면 Python의 **개인 네트워크** 연결을 허용하세요. 프로그램이 방화벽이나 운영체제 인증서 저장소를 자동 변경하지는 않습니다. 포트는 주문 HTTPS `9443`, 인증서 안내 HTTP `9080`입니다. PC 전용 모드의 `8443` 서버와 구분됩니다. 시연 중 모든 매장/주방창은 **아이폰 시연 모드로 실행한 운영 센터**에서 여세요.

PC에 여러 네트워크/VPN이 있어 주소가 잘못 선택되면 PowerShell에서 `$env:BDS_DEMO_IP='192.168.0.10'`처럼 실제 와이파이 IPv4를 설정한 뒤 실행합니다. IP가 바뀌면 다시 실행해 서버 인증서를 갱신하고 새 주소로 앱을 설치하세요. 주소가 달라지면 이전 앱의 주문 저장 공간도 달라집니다.

## 푸시 조건과 시연 범위

- iOS/iPadOS **16.4 이상**, 홈 화면에 설치한 웹 앱, 사용자 탭으로 알림 허용, 신뢰된 HTTPS가 필요합니다. Safari 일반 탭만으로 시연하지 마세요.
- 서버는 PC에서만 실행하지만 푸시 전달은 Apple 등의 푸시 서비스를 거칩니다. **PC와 아이폰 모두 인터넷 연결**이 필요합니다. 완전히 외부망이 없는 LAN에서는 앱 내 상태 확인만 가능합니다.
- PC 서버/운영 센터를 켜 두세요. PC 절전, 방화벽, VPN, 집중 모드, 알림 권한, 네트워크 상태가 전달에 영향을 줄 수 있습니다.
- 서버 발송 대기열/재시도와 브라우저 주문 흐름은 자동 검증했습니다. **실제 아이폰 잠금 화면 수신은 위 절차로 기기에서 최종 확인해야 합니다.** 브라우저 테스트는 실제 Apple 푸시 수신을 대신하지 않습니다.
- 주문 기록은 해당 브라우저/홈 화면 앱의 무작위 기기 토큰으로 구분됩니다. 회원가입/로그인이나 기기 간 기록 동기화는 없습니다. Safari와 설치 앱이 저장 공간을 공유한다고 가정하지 않습니다. 데이터 삭제 시 기존 주문 접근이 사라집니다.
- 결제/취소/재고/영업시간 관리와 앱스토어 배포는 이 시연 범위에 포함하지 않습니다.

## 데이터와 유지보수

발표용 보호 장치: 모바일 주문/알림 등록은 접속 IP당 합계 분당 20회로 제한합니다(초과 시 429, 60초 후 재시도). 기기당 진행 중 주문 3건, 푸시 구독 3개이며 서버 전체는 진행 중 앱 주문 200건, 구독 300개까지 허용합니다. 동일 주문 요청의 재시도는 주문 건수를 추가하지 않습니다. IP 제한은 단일 서버 메모리 기준이며 재시작하면 초기화됩니다. 회원 인증이나 운영용 공격 방어를 대체하지 않습니다.

PC 클라이언트도 HTTPS 인증서를 검증합니다. 아이폰 시연 모드는 기존 로컬 CA를 `BDS_SSL_CA`로 지정하므로 아이폰의 인증서를 다시 설치할 필요가 없습니다. PC 전용 모드는 해당 PC의 `cert.pem`을 신뢰합니다. 보안 수정 후에는 기존 운영 센터와 해당 서버를 종료한 뒤 `start.bat`을 다시 실행하세요.

| 목적 | 파일 |
|---|---|
| 모바일 화면/스타일 | `mobile/app.js`, `mobile/style.css`, `mobile/index.html` |
| 모바일 HTTP/기기 토큰 | `mobile/api.js` |
| 설치/푸시 수신/클릭 | `mobile/manifest.webmanifest`, `mobile/sw.js`, `mobile/push.js` |
| 모바일 API/검증 규격 | `kiosk/api/mobile.py`, `kiosk/mobile_schemas.py` |
| 주문 저장/서버 가격/중복 방지 | `kiosk/storage/orders.py` |
| 고객별 조회 | `kiosk/storage/mobile.py` |
| DB 변경/푸시 구독/대기열 | `kiosk/storage/migrations.py`, `kiosk/storage/push.py` |
| 푸시 발송/재시도/키 | `kiosk/push.py` |
| LAN 주소/인증서/설치 안내 서버 | `kiosk/mobile_demo.py` |

`order_id`는 기존 정수 기본키를 유지하고 `order_source=APP` 주문만 표시번호에 `A`를 붙입니다. 전체 주문 순번을 공유하므로 앱 주문이 A001, A004처럼 건너뛸 수 있습니다. 키오스크는 002처럼 표시합니다. DB 마이그레이션은 기존 주문을 삭제하지 않고 열/인덱스/푸시 테이블을 추가합니다. 신규 주문은 서버 메뉴 가격을 저장합니다.

모바일 요청은 가격/주문 출처를 직접 정하지 못하며, 기기 토큰과 UUID 요청번호를 사용합니다. 전송 실패 시 같은 요청번호로 재시도해 중복 저장을 막습니다. 주방/API 공유 키는 모바일 정적 파일에 넣지 않습니다. 로컬 관리자 비밀번호와 기존 관리자 API 키 인증은 별개입니다.

푸시는 주문 상태 변경 트랜잭션에 대기열을 함께 기록하고 별도 작업 스레드가 발송합니다. 실패는 최대 8회 재시도하며 만료된 구독(404/410)은 삭제합니다. 중단 후 재시작하면 미발송 대기열을 이어서 처리합니다. 전달은 at-least-once 방식이므로 알림 태그로 중복 표시를 줄이며 정확히 한 번의 수신을 보장하지 않습니다.

`.local/vapid.pem`은 푸시 서명 개인 키입니다. 삭제/교체하면 기존 기기의 구독을 해제 후 다시 등록해야 합니다. `.local/mobile-demo/ca-key.pem`은 로컬 인증기관 개인 키입니다. **`.local` 전체를 Git/공유 자료에 넣지 마세요.** 인증서 설치 안내는 공개 `.cer` 파일만 제공합니다. 시연 종료 후 아이폰의 해당 프로파일을 삭제할 수 있습니다.

## 검증 명령

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
$env:BDS_DISABLE_PUSH_WORKER='1'
.venv/Scripts/python.exe -m unittest discover -s tests -v
.venv/Scripts/python.exe tests/mobile_browser_smoke.py
```

브라우저 검증은 설치된 Windows Edge를 사용하고 임시 DB/서버를 정리합니다. 스크린샷은 `logs/mobile-review/`에 저장합니다. 실제 시연을 시작할 때는 테스트용 `BDS_DISABLE_PUSH_WORKER` 환경 변수를 제거하세요.

## 참고

매장 선택/메뉴 주문/픽업 흐름은 [스타벅스 공식 앱 안내](https://www.starbucks.co.kr/util/app_tip.do)를 참고했습니다. 로고나 화면 자산을 복제하지 않았습니다. iPhone 설치형 웹 앱 푸시 조건은 [WebKit 공식 iOS 16.4 안내](https://webkit.org/blog/13878/)와 [Apple Web Push 문서](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers?language=objc)를 기준으로 구현했습니다.
